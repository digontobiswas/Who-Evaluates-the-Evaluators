\section{Introduction}
\label{sec:intro}

Progress in end-to-end autonomous driving is measured by benchmarks.
Real-world closed-loop testing is unavailable at research scale, so policies are ranked by proxy
evaluators: displacement from a logged human trajectory~\cite{zhai2023admlp,li2024egostatus},
non-reactive pseudo-simulation such as NAVSIM~\cite{dauner2024navsim}, two-stage
pseudo-simulation~\cite{cao2025pseudosim}, and closed-loop simulators such as
Bench2Drive~\cite{jia2024bench2drive} or BridgeSim~\cite{zhao2026bridgesim}.
Papers routinely report gains of one or two points on these scores.
Whether such a gain means better driving depends on a property of the evaluator that is rarely
measured: does it rank policies in their true order?

Existing studies answer a weaker question.
They correlate the published numbers of a handful of methods across benchmarks~\cite{wang2026olcl},
or document that open-loop and closed-loop scores of the same policies differ~\cite{zhao2026bridgesim}.
In both cases evaluator is compared with evaluator.
Without a ground truth a disagreement cannot say which side is wrong, and an agreement can be shared
bias.

We remove this obstacle by constructing policies whose order is known
(\cref{sec:method:popA}).
A pretrained policy whose plan is delayed, or drifted sideways, in graded steps must drive worse as the
step grows; an evaluator that does not recover this order is blind to that failure.
Two safeguards make the construction usable.
First, ``more degradation is worse'' is itself an assumption about the world, so it is tested: a family
is admitted only if a closed-loop reference ranks all of its levels with statistical confidence, and,
to avoid circularity, this selection is made on one set of scenes while every evaluator is measured on
disjoint scenes (\cref{sec:method:mono}).
Second, recovering a degradation order is necessary but not sufficient.
An evaluator that penalises every change to the plan recovers every order and still mis-ranks real
policies.
We therefore add a \emph{specificity arm} (\cref{sec:method:spec}): the same edits applied only to the
part of a plan that a replanning controller never executes, which a valid evaluator must leave
unpenalised.

We apply the protocol to five evaluators that can be run on the same scenes---open-loop average
displacement error (L2), NAVSIM v1 PDMS, NAVSIM v2 EPDMS in one stage and two stages, and the
closed-loop simulator BridgeSim as reference---and to four policy families, including the diffusion
planner DiffusionDrive, which is never used to select anything.
\Cref{fig:specificity} summarises the central result.
Both NAVSIM versions penalise a lateral edit beyond the first $1.5$\,s of the plan by
\num{SpecPctNavsimVtwo}--\num{SpecPctNavsimVone} of the penalty for the same edit applied to the whole
plan; closed loop, which never executes that part, does not move.
Open-loop L2 is the most sample-efficient detector of every known failure and is also non-specific:
sensitivity is not validity.
On real policies, NAVSIM and closed loop disagree on held-out scenes far beyond the closed-loop
test--retest ceiling.

\paragraph{Contributions.}
\begin{itemize}
\item A ground-truth ordering test for driving evaluators whose ordering is itself validated in closed
loop on scenes disjoint from those used for measurement (\cref{sec:method}).
\item A specificity test that separates evaluators which detect bad driving from those which detect any
change to the plan, and evidence that both NAVSIM versions fail it (\cref{sec:results:spec}).
\item A controlled study of five evaluators and four policy families with paired bootstrap intervals,
seed replication, a held-out policy, held-out scenes and a closed-loop test--retest ceiling
(\cref{sec:results}).
\item An open harness and all per-scenario scores.
\end{itemize}
